## §2. 밸런스 근거 — 왜 이 숫자인가

한 번 갈아엎었다. 처음 값으로는 **군량이 병력을 못 따라가 아무도 출병하지 못했다.**

| 값 | 지금 | 왜 |
|---|---|---|
| 병력 상한 `15000 + size*13000` | 대도시 8만 | 처음엔 `30000+size*26000`(16만) 이었는데 수확이 못 먹여 살렸다 |
| 수확 `land * 40` | 대도시 약 5.9만석/년 | `*30` 이면 주둔 소비에도 못 미쳤다 |
| 주둔 소비 `troops * 0.08`/월 | 2.4만 병력 = 1,920석/월 | 수확 대비 여유 3할 |
| 금 수입 `comm * 0.75 * …` | 대도시 300~1,250/월 | `*0.40` 은 커맨드 두 개도 못 굴렸다 (내정 1회 = 120금) |
| 초기 군량 `pop * 0.12` | 2~3년치 | 첫 출병이 가능한 최소선 |
| 원정 군량 `병력 × 1.0` | 한 달치 | `×1.2` 는 첫 턴 출병을 막았다 |

**전투 계산 (`unitPower`)**

```
전투력 = 병력 × (0.35 + 지휘/155) × (0.55 + 사기/215) × (0.62 + 훈련/260)
         × 무기(기술) × 지형 × 병종상성 × [성벽]
피해 = 공격측병력 × 0.062 × ratio,  ratio = clamp(공/방, 0.40, 2.60)
반격 = 방어측병력 × 0.034 / ratio   (원거리는 반격 없음)
```

- `ratio` 하한을 0.32 → **0.40** 으로 올렸다. 0.32 에서는 불리한 공격이 학살 수준이었다
  (공격측 925 잃고 23 입힘).
- 성 안 방어 보정: **성문이 성할 때만** `wallBonus`(1.0~1.8), 뚫린 뒤에는 1.12.
  안 그러면 성문을 부수고 들어가도 전멸했다.
- `본성` 지형 방어를 1.60 → **1.25** 로 낮췄다. 위 보정과 겹쳐 3배 가까이 됐었다.

**AI 출병 조건** — 세력이 안 줄어드는 문제를 이걸로 잡았다.

- 병력비 `보내는 병력 / (적 병력 × 1.25)` 가 **1.45** 이상일 때만 친다 (성벽 몫 1.25).
- 보내는 병력을 70% → **85%** 로 올렸다.
- `zeal = 0.18 + 야망×0.022 + min(0.24, 성 수×0.016)` — 큰 세력이 더 자주 움직인다.
- **후방 성이 국경 성으로 병력·금·군량을 밀어 준다** (`forwardSupply`).
  이게 없으면 큰 세력도 힘을 못 모아서 소모전만 반복했다. 통합의 8할이 이 한 함수다.
- 목표 가치에 `weak = 내 국력 / 상대 국력` (0.45~3.2) 을 곱한다. 약한 쪽부터 먹는다.

### 5.2 고친 것

**지도 렌더를 둘로 갈랐다.** 땅·강·주 이름·길은 `ctx.scale` 안에서 그리고,
**도시 표식과 이름은 화면 좌표로 따로 그린다.** 전부 배율을 먹이면 폰에서 글씨가 5px 이 된다.
표식 크기도 `clamp(scale, 0.62, 1.25)` 로 바닥을 깔아 손으로 짚을 만큼은 남긴다.

**확대·이동을 넣었다.** 휠·핀치로 1~4배, 끌어서 이동, 두 번 누르면 전체 보기(`fit()`).
끌었으면 클릭 판정을 안 한다(`_dragged`). 도시 탭 반경은 화면 22px 고정.

**이름표 충돌 회피.** 아래에 놓되 겹치면 위로 올린다(`_cities` 의 `placed` 배열).
800×360 최대 축소에서 겹침 4 → 2, 1.8배만 당기면 0. 데스크톱은 0.

**레이아웃은 좁아져도 가로를 지킨다.**
- `@media (max-height: 560px)` — 상단바 한 줄(31px), 로그바 숨김 → **기록 버튼**으로 본다,
  날짜는 `건안 5년(200년) 2월` → `200년 2월`, 부가 지표(`.opt`)는 숨김
- 전투 옆패널의 행동 버튼을 3열로 — 줄 수를 줄여 스크롤 없이 다 보이게
- 넓은 표(출진 편성·무장 일람)는 `.scroll-x` 로 가로 스크롤
- 세로로 들면 **"가로로 돌려 주시오"** 오버레이 (`#rotate`, 860px 이하 세로에서만)

### 5.3 이 과정에서 잡은 진짜 버그

1. **중복 id.** 헤더의 "아군 차례" 뱃지와 전투 옆패널이 **둘 다 `battle-side`** 였다.
   CSS 의 패널 폭 규칙이 뱃지에도 걸리고, `$('#battle-side')` 는 뱃지를 집었다.
   → 뱃지를 `battle-turn` 으로 바꿨다. **`tools/imports.mjs` 가 이제 중복·미아 id 를 검사한다.**
2. **`euro(숫자)` 크래시.** `josa()` 가 `word.charCodeAt` 을 부르는데 숫자가 들어오면 죽는다.
   상인의 군량 구입에서 터질 자리였다. → `josa` 가 숫자를 받도록 고치고
   (1·3·6·7·8·0 은 받침 있음으로 본다), `-(으)로` 는 ㄹ 받침 규칙이 달라 `euro` 를 따로 구현했다.
3. **조사 오류 여럿.** `${from.name}을 떠나`, `${iga(f.name)}군이`(→ "조조가군이"),
   `${kind}을 맡았다`(치수을) 등. → **`tools/josa-scan.mjs`** 가 보간 뒤에 조사가
   박힌 자리를 전부 찾아낸다. 지금 0곳.
4. 캔버스가 0×0 일 때(숨은 탭에서 열림) 영영 안 그려지던 것 → 다음 프레임에 재시도.

> "명령이 성 정보 하단에 있어서 스크롤 해야 볼수있으니 불편하다"

`#cmdbar` — 지도 왼쪽 고정 세로바(데스크톱 78px / 폰 60px).
내정·군사·인사·계략·외교·상인 + 맨 아래 **출진**(붉은 버튼).
적 성을 고르면 `군사 / 출진` 만 남고, 인접한 아군 성이 없으면 그것도 안 나온다.

### 성 정보 / 무장을 탭으로 갈랐다

> "무장정보도 성 정보랑 탭으로 전환하는게 나아보여"

`sideTab` 이 모듈 수준 변수라 **도시를 바꿔도 보던 탭이 유지된다.**
무장 탭 라벨에 인원수가 붙는다(`무장 8`).

`.meter` / `.meter-h` 를 CSS 로 빼고 폰에서 눈금을 조여, 800×360 에서
**성 정보·무장 두 탭 모두 스크롤 없이** 들어간다(둘 다 329/329).

### 군주는 사로잡아도 거둘 수 없다

> "군주가 포로로 잡혔는데 군주는 참수 / 해방 둘중 하나만"

`state.js` 에 `isRulerOf(st, s)` 를 뒀다 — **살아 있는** 세력의 군주인지.
UI(무장 상세·전투 후 포로 처분), `captiveAction`, AI 세 곳 모두 이걸 본다.
군주면 등용 버튼이 아예 안 나오고 설명이 붙는다.

**세력이 무너지면 군주가 아니게 된다.** 그래서 `turn.js` 의 멸망 처리에서
`factionOfficers`(normal 만) 대신 **그 세력 소속 전원**을 재야로 돌린다 —
안 그러면 갇힌 군주가 등용도 석방도 애매한 채로 영영 남는다.
`smoke.mjs` 가 이 두 경우를 다 검사한다.

### 이 과정에서 걸린 함정

**로컬에서 서비스워커가 옛 모듈을 먹였다.** 코드를 고치고 새로고침해도 캐시된
`city.js` 가 돌아서 "고쳤는데 왜 그대로지?" 를 한참 했다.
→ `main.js` 가 **localhost 에서는 서비스워커를 등록하지 않고, 이미 있으면 벗겨낸다.**
배포 환경에서만 등록된다. (그래도 배포할 때 `CACHE` 버전은 꼭 올려라.)

## §6.55 손맛 손질 (플레이 피드백 2차)

- **페이지 확대 차단.** `body { touch-action: pan-x pan-y }` — 훑어 넘기기만 허용하니
  핀치도 두 번 두드리기도 확대되지 않는다. 지도(`#map`)와 전장(`#bmap`)은
  `touch-action: none` 이라 브라우저가 손대지 않고 제 확대 코드가 직접 받는다.
  `viewport` 에 `maximum-scale=1`, 옛 웹킷용 `gesture*` 차단은 보험.
  **두 번 두드리기를 JS 로 막지 마라** — 멀쩡한 빠른 탭까지 먹는다. 한 번 넣었다가 뺐다.
- **메뉴창 바깥을 누르면 닫힌다.** 창 안에서 시작한 누름이 바깥에서 끝나면 닫지 않는다
  (밀어서 고르다 손이 나가는 경우). `dom.js` 의 `downOnBackdrop`.
  제목줄에 ✕ 를 넣고, 제목줄·버튼줄을 `sticky` 로 붙여 목록이 길어도 닫기가 손에 닿는다.
- `mapview` 의 `setPointerCapture` 를 `try/catch` 로 감쌌다. 붙잡기가 실패하면
  조작 전체가 죽던 자리다.

### 숨은 탭에서는 자동전투가 멈춘 것처럼 보인다

브라우저가 백그라운드 탭의 `setTimeout` 을 1분에 한 번꼴로 조인다.
`auto()` 가 `await sleep(70)` 으로 도니 화면을 가리면 사실상 멈춘다.
**버그가 아니다** — 돌아오면 이어서 돈다. 개발 중에 이걸로 한참 헤맸다.

## §6.56 완전 전체화면 (몰입 모드)

> "핸드폰 위아래 여백이 생기고 버튼바가 뜨는데 일반 게임처럼 완전 전체화면은 안 되나"

- `manifest.webmanifest` → `"display": "fullscreen"` (+ `display_override`)
- TWA → `twa-manifest.json` 의 `"display": "fullscreen"` 이면 bubblewrap 이
  `DISPLAY_MODE = immersive` 를 내보낸다. **손으로 `sticky-immersive` 로 고친다** —
  쓸어 올려 막대를 불러도 곧 다시 숨는다. 게임에는 이쪽이 맞다.
- 화면 끝까지 그리게 되므로 노치·둥근 모서리 대비가 필요하다.
  가장자리에 닿는 요소만 `env(safe-area-inset-*)` 만큼 안쪽으로 민다
  (`#topbar #battle-top #cmdbar #side #battle-side #logbar`). 캔버스는 끝까지 채운다.

**여백은 `--px` 변수를 거쳐 `max(원래값, 안전여백)` 으로 잡는다.**
처음에 고정값으로 썼다가 폰용 압축 패딩(`3px 8px`)까지 덮어써서 상단바가 다시 두꺼워졌다.
미디어 쿼리마다 `--px` 를 두어 원래 값을 지킨다. **이 규칙은 CSS 맨 끝에 있어야 한다** —
위의 미디어 쿼리들이 `padding` 을 통째로 다시 쓰기 때문이다.

## §6.57 가로 전환은 첫 손짓에 (전용 단추 없음)

앱 안드로이드 쪽 배선(§6.2)만으로는 기기에 따라 가로가 안 잡힌다.
그래서 웹에서도 건다. **`main.js` 의 `ensureLandscape()`** — 세 자리에서 부른다.

1. 여는 즉시 (설치형일 때만)
2. **document 의 첫 `pointerdown`** — 어차피 시나리오를 누르려면 화면을 건드린다.
   사람이 누른 직후라 가장 잘 듣는다. 성공하면 리스너를 뗀다.
3. `visibilitychange` — 뒤로 갔다 오면 풀리는 환경이 있다

먼저 그냥 `screen.orientation.lock('landscape')` 를 걸고, 실패하면 전체화면을 잡고 다시 건다.
**호출이 겹치므로 in-flight 약속을 공유한다** — 첫 손짓과 안내 화면 처리가 같이 들어와
시도가 두 번 돌고 진단 문구가 두 번 쌓이던 것을 그걸로 막았다.

세로 안내 화면(`#rotate`)은 **어디를 눌러도** 걸린다. 실패하면 그 자리에 이유를 찍는다 —
조용히 실패하면 원인을 알 길이 없어 한참 헤맨다.

## §6.58 전투 화면 — 병종 실루엣과 범위 표시

- **부대 모양이 병종을 말한다.** 색(아군 파랑 / 적군 빨강)만으로는 한눈에 안 들어왔다.
  `_unitPath()` — 보병 방패 / 기병 화살촉(나아가는 쪽이 뾰족) / 궁병 삼각 / 수군 선체+돛대.
  삼각·배는 무게중심이 아래라 이름을 조금 내려 찍는다.
- **범위 표시는 셋을 같이 준다** (`_highlights()`). 지형 색이 다양해서 옅게 칠하기만 하면 묻힌다.
  칠 + **영역 바깥 테두리**(어두운 밑선 위 밝은 선) + 칸마다 표식(이동 점 / 공격 십자) + 느린 맥박.
  테두리는 경계 변만 그린다 — 안쪽 격자와 겹치면 지저분하다.
  꼭짓점 e 와 이웃 방향의 대응은 `EDGE_DIR = [1,0,5,4,3,2]` (map.js 의 `DIRS` 순서 기준).

**맥박 때문에 매 프레임 다시 그린다.** 그래서 길찾기는 `render()` 에서 한 번만 돌려
`this._reach` 에 담아 둔다 — `draw()` 안에서 `moveOptions()` 를 부르면 초당 수십 번 돈다.
맥박은 부대를 고른 동안에만 돌고 20fps 로 조인다(폰 배터리).

## §6.59 전투 화면 그림 — `src/ui/battleart.js`

> "유닛 모양이나 맵이 너무 투박한데 좀더 디테일하게"

**battleview 는 조작과 흐름, battleart 는 붓질.** 둘을 한 파일에 두면 둘 다 읽기 어렵다.

- 병사: 보병(창·방패) / 기병(말 위 작은 기수) / 궁병(활) / 수군(선체·노·돛).
  **`figureCount()` 가 병력에 따라 인원 수를 정한다** — 보병·궁병 1~5, 기병 1~3.
  배는 인원 대신 크기와 노 수로 표현한다.
- 지형: 나무·산봉우리와 눈·늪 웅덩이·사구·물결·바퀴자국·성벽 돌 쌓기·성문 판자·본성 바닥돌.
  장식 위치는 **타일 좌표 해시**라 같은 성은 늘 같은 그림이다.
  `s`(육각 반지름)가 11px 아래면 스스로 생략한다.

**지형은 오프스크린에 구워 blit 한다**(`_ensureTerrain`). 맥박이 20fps 로 도는데
221칸을 매 프레임 다시 그리면 폰이 버겁다. `render()` 때만 다시 굽는다.

### 여기서 밟은 것

1. **`hexPath` 가 `this.g` 를 붙박이로 썼다.** 오프스크린 컨텍스트에는 경로가 안 잡혀
   `fill()` 이 빈 경로를 칠했고, 지형 레이어가 3% 만 그려졌다.
   → 컨텍스트를 인자로 받게 고쳤다. **캔버스를 여러 개 쓰기 시작하면 제일 먼저 의심할 곳.**
2. **이름표 자리.** 칸 아래에 두면 육각형이 1.5s 간격으로 쌓이는 탓에 경계에 걸려
   *아래 칸의 이름*처럼 보인다. → 위쪽 막대 바로 밑으로 올리고 두 자로 줄였다.
3. 처음엔 이름표가 병사 머리를 덮었다. 칸 높이 2s 안에 막대·이름·병사를 다 넣어야 해서
   자리 다툼이 심하다. 지금 배치는 막대 −0.98s / 이름 −0.72s / 대열 +0.04s~+0.34s / 그늘 +0.62s.

### 그림을 눈으로 못 볼 때

`tools/serve.mjs` 에 **`/__shot`** 을 뒀다. 개발 서버에만 있다.

```js
fetch('/__shot?name=battle', { method:'POST', body: canvas.toDataURL('image/png') })
// → tools/shots/battle.png
```

헤드리스·숨은 탭이라 화면을 볼 수 없을 때 결과를 꺼내 확인하는 창구다.
이걸 만들기 전까지는 색 표본만 세면서 짐작했고, 그 탓에 위 1번을 늦게 찾았다.

## §6.60 배와 병종 — 전략의 축을 둘 늘렸다

### 배 (`src/data/ships.js`)

**수군은 병종이 아니다.** 뭍에서는 아무 쓸모가 없고, 물 타일에 들어가야 쓰인다.

- 출진할 때 배를 가져갈지 고른다. 등급은 **출발하는 성의 기술**이 제한한다
  (`availableShips(tech/cap)`) — 소선 0.15 / 중선 0.40 / 대선 0.62 / 누선 0.82.
  부대당 금이 든다. **기술 내정이 드디어 값을 한다.**
- 안 가져가면 물에서 **뗏목**을 엮는다 — 전투력 ×0.55, 이동 3.
- 가져갔으면 그 배로 모양(선체 폭·층집·노 수·돛 높이)과 성능이 바뀐다.
- **수전 여부는 길이 정한다** — `ROUTES` 의 `water` 로 이어진 성을 치면 수전 전장.
  무엇을 데려갔느냐로 정하던 것을 바꿨다. 이래야 "적벽으로 가려면 배가 있어야 한다"가 성립한다.
- 지키는 쪽은 제 성의 기술로 지을 수 있는 가장 좋은 배를 **공짜로** 갖고 있다.
- 물에서는 병종 상성 대신 배가 힘을 정하고, 지휘는 육지 대신 **수지**를 쓴다.
  물에 떠 있는 적을 뭍에서 치면 ×1.18.

### 병종 고정 (`officers.js` 의 `troopType`)

출진할 때 고르지 못한다. **누구를 데려가느냐가 곧 부대 구성이다.**

삼각관계: **기병 > 궁병 > 보병 > 기병**. 지형이 그 위에 얹힌다
(기병은 평지 ×1.14·산숲 ×0.9, 보병은 산숲 ×1.1).

## §6.61 병종은 능력치가 아니라 열전으로 (§6.60 을 뒤집었다)

처음엔 능력치로 병종을 뽑았다 — `무력≥76 & 육지≥62 → 기병`, `지력≥76 → 궁병`, 나머지 보병.
플레이해 보니 **"능력치 좋으면 다 기병"** 이었다. 규칙이 이름난 무장을 전부 한 칸으로 몰았고,
그러면 데려갈 사람을 고를 이유가 없어진다. 규칙을 통째로 버렸다.

이제 병종은 **무장마다 데이터에 박혀 있다.** `officers.js` 408줄 전부에 `#기병`/`#궁병`/`#보병` 중 하나.

```js
export function troopType(o) {
  const t = o.tags.find((x) => TROOP_TAGS.includes(x));
  if (t) return t;
  return '보병';   // 여기 오면 데이터가 빠진 것 — smoke.mjs 가 잡는다
}
```

- 배정 근거는 `tools/assign-troops.mjs` 에 이름 목록으로 남겼다.
  **열전 근거 396명**(마초·여포는 기병, 황충·하후연은 활, 전위·허저는 발,
  책사·문관은 뒷줄이라 궁병), 근거가 없는 **12명만 균형으로** 채웠다.
  이미 태그가 있는 줄은 건드리지 않으므로 손으로 고친 것은 다시 돌려도 안전하다.
- 지금 분포 — **기병 138 · 궁병 129 · 보병 141**.
- `smoke.mjs` 가 ① 태그 빠진 무장 0명 ② 어느 병종도 22~45% 밖으로 안 나감
  ③ 관우·여포·마초=기병, 황충·하후연·제갈량=궁병, 전위·허저·고순=보병 을 못으로 검사한다.

> 규칙으로 뽑을 수 있는 것과 데이터로 박아야 하는 것은 다르다.
> **성격에 해당하는 값은 규칙이 아니라 데이터다.**

## §6.62 해마다 자란다 (`annualGrowth`)

매년 **1월**, 살아있는 무장의 능력치가 하나씩 오른다. `endMonth` 의 1월 블록에서 돈다.

눈금은 사용자가 준 것 — **무장 하나가 10년에 5**. 한 번에 1씩 올리므로 성장 확률의 평균이
해마다 0.5여야 한다. 나이로 갈랐다:

| 나이 | 확률 |
|---|---|
| ~24 | 0.85 |
| 25~34 | 0.62 |
| 35~44 | 0.42 |
| 45~54 | 0.26 |
| 55~ | 0.12 |

- 오를 항목은 **낮은 쪽에 가중치** (`1 + (100-현재)/25`, 1~4배). 못 하는 것을 익히는 편이
  자연스럽고, 잘하는 무장만 계속 강해지는 것도 막는다. 100은 넘지 않는다.
- 자란 값은 `s.growth = {lead: 3, ...}` 로 무장 상태에 쌓인다. **`base()` 는 안 건드린다** —
  `eff()` 가 `타고난 값 + 자란 값 + 보물` 로 합쳐 주고, 전투·내정 판정은 전부 `eff()` 를 쓴다.
  세이브는 `s` 를 통째로 직렬화하므로 따로 손댈 곳이 없었다.
- 보고: 400명이 자라니 전부 알리면 월말 보고가 넘친다. **우리 무장만, 다섯 줄까지.**
  무장 상세 화면에는 자란 만큼을 `+n` 으로 붙였다.

실측 (194 시나리오, 120개월):

```
10년 — 생존 163명, 평균 +5.26 (목표 5)
        30세 미만 +6.35 / 50세 이상 +2.33
20년 — 생존 112명, 평균 +8.19
```

20년 쪽이 10을 못 채우는 건 그 사이에 다들 나이를 먹기 때문이다 — 의도한 모양이다.
`smoke.mjs` 가 10년 평균 3.5~7, 젊은 쪽 > 늙은 쪽, 1~100 범위, 세이브 왕복을 검사한다.

## §6.6 배포 절차 — 매번 이 셋을 같이 올려라

> "고쳤는데 폰 화면이 그대로다" 의 원인은 거의 항상 서비스워커 캐시다.

| 고칠 것 | 파일 |
|---|---|
| 캐시 버전 | `sw.js` 의 `CACHE` (`sam-v3` → `sam-v4`) |
| 판 번호 | `src/version.js` 의 `BUILD` — **타이틀 구석에 찍힌다** |
| 모듈 목록 | 파일을 추가·삭제했으면 `sw.js` 의 `APP_SHELL` (`tools/imports.mjs` 가 검사) |

`main.js` 가 열 때마다 `reg.update()` 로 새 워커를 확인하고, 자리를 잡으면
`controllerchange` 에서 **스스로 한 번 다시 불러온다**(플래그로 무한 새로고침 방지).
그래도 안 바뀌면 타이틀의 판 번호를 보면 된다 — 안 올라갔으면 아직 옛 파일이다.

**localhost 에서는 서비스워커를 아예 등록하지 않는다**(이미 있으면 벗겨낸다).
개발 중에 캐시가 옛 모듈을 먹이는 함정을 한 번 크게 밟아서 그렇게 했다.
